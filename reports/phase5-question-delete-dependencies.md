# Phase 5: Delete question dependencies with confirmation

Version 0.6.27. Single/bulk question deletion previews name all current dependent automations (including paused) and notification rules. The configuration fingerprint now includes automation identity/revision/configuration, so new or changed dependencies after the preview require fresh confirmation. Changing observation counts remains allowed under the existing all-data-for-question contract.

Confirmed configuration deletion removes those automations and current rules with their question data. It removes target question Activity/alerts/deliveries, cancels remaining pending jobs from deleted automations, and purges matching notification-rule revisions/state. A rule moved to another question keeps its current unrelated definition/version/state and unrelated historical metadata. Reusable actions, uploaded audio and protected action settings are retained. Normal history-only deletion still disables dependencies rather than deleting configuration.

The existing transaction now waits for the Actions lock as well as pipeline/reliable guards before purging. Existing progress display/event-loop offload remain. Immutable rule-version delete protection is suspended/restored only inside the deletion transaction, following the established camera-purge pattern; rollback restores configuration and protections. No real question or dependency was deleted by this change; no automatic retroactive cleanup runs on startup.
